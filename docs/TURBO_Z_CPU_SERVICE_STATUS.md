## CPU reply ownership

The PCG controller holds its captured font read/address while waiting for both
the video-window roundtrip and font validity. It has no separate response ACK.
The bridge keeps the arbiter reply owned until PCG lowers that read after
capturing data. Font validity cannot release CPU WAIT before the VID handshake;
VID acknowledgement cannot release it before the font response.

Read/address pass directly from PCG to the arbiter. The bridge supplies valid
data only during the corresponding read and suppresses delivery on cancellation.
An invalid response supplies zero data. CPU cancellation must reach the arbiter
too: the bridge cannot discard DDR ownership. Preserve the raw read during a
cancel pulse. Gating it low would rearm the arbiter and allow the same old PCG
request to be admitted again when cancel falls. PCG/CPU reset retires that old
request; it does not reset the font transport.

The fixture implements consumer hold with actual CPU reset, video-local reset
release, and a two-stage SYS observation of the held video reset. The lifecycle
coordinator still drains cache/arbiter ownership before frontend cancellation.
This is functional reset dispatch inside a diagnostic, not Main/OSD dispatch
or physical reset/CDC placement acceptance.

## Diagnostic and independent oracle

One ordered index-5 upload supplies all 262,144 generated font bytes through
the real frontend and a delayed/BUSY mock DDR. No font reupload occurs across
six CPU boot attempts. Four attempts execute the complete original diagnostic;
one is interrupted after a cancelled read drains while the old PCG level stays
high, and another is reset with a real CPU DDR response still owned. Neither
interrupted attempt may write the success marker. Both recover through later
complete boots with retained font readiness/bytes.

Each complete boot uses real OUT instructions to program the unique highest
selector cells, including neighboring distractor writes. It checks both font
levels, all sixteen banks, both halves, four character codes (00/7F/80/FF)
and four rows (0/1/7/15). It then checks ANK exit, incompatible PCG attributes,
an ignored Kanji ROM write and sixteen actual INI stores/readbacks over every
row of the highest glyph. The diagnostic writes its own success/failure marker
and HALTs. Test code does not inject result stores or force chip/CPU state.

Per positive configuration: 4,162 actual external CPU reads include two
cancelled requests; 4,168 completed IN/INI reads come from the four full boots.
The cache independently refills the highest cell throughout CPU execution,
with continuously checked VID data/tags/descriptors and invalidation misses.
Cache requests queued behind cancelled CPU ownership must still drain. Cache
updates here are generated by the fixture, not by CPU text/attribute writes.

A separate Python emitter reproduces the complete 65,536-byte diagnostic RAM
image. It must match the actual pre-boot image for every positive and mutant.
The independent bus oracle checks every completed CPU port, physical font
address and sampled byte for boots 1/2/4/6. The physical address comes from
observed real selector writes and I/O addresses, not DUT selection outputs.
Independent pending-intent/round-robin and DDR word/lane/payload ledgers also
check actual transport. Completed renderer bytes are synthetic cache scans,
not machine RGB pixels.

All clocks and stalls are deterministic: SYS 32 MHz; CPU enables at 4 or 2 MHz;
VID half-period 11,640 ps (rounded nominal X3), with a separate 20,000-ps
functional stress case. The video window is a synthetic four-edge interval
every 128 VID edges, not an actual CRTC/HSYNC signal or native ASIC timing.
Each complete boot's first CPU response is delayed 200 SYS cycles (6.25 us),
beyond an entire window at either VID rate. Separate indefinitely held replies
provide the actual cancellation/reset ownership witnesses.

## Remaining machine boundary

The eventual shared-machine wiring is `cg_bus.kanji_cpu_read/addr` through the
bridge to arbiter CPU read/address, with bridge valid/data returning to
`cg_bus.kanji_cpu_valid/q`. The bridge and arbiter must share cancellation,
while PCG reset/consumer hold preserves the demonstrated drain order. This
fixture does not enable that wiring in `rtl/sharpx1.v`, qualify missing-font
boot behavior, add a snapshot identity or prove other devices coexist.

Real CPU text/attribute/Kanji writes still need one accepted cache update per
transaction and a coherent descriptor publication policy in the machine. The
later [standalone writer gate](TURBO_Z_VRAM_WRITE_STATUS.md) now qualifies that
boundary with actual TV80/VRAM/cache execution; machine wiring remains open. The renderer in
`rtl/legacy/x1_vid.v` currently captures live RAM bytes at its request phase;
external backing must consume the committed cache descriptor with its glyph.
In particular, a cache offset's half selector must agree with the committed
Kanji metadata. Using live `kan_vid[6]` with an older published descriptor
would mix versions even if every glyph byte were present. The later standalone
cache-half extension selects a committed descriptor bit internally, retaining
caller selection by default. Actual renderer integration still needs that
coherent packet. Refill-before-write WAIT/native visibility, broader raster/
ANK/PCG behavior and real RGB pixel/reset gates remain open.

No combined board fit, STA/physical CDC, DDR allocation, RBF, native firmware
or MiSTer result follows. The initial 138-M10K probe is historical;
the available MiSTer at `10.0.2.14` was not contacted or loaded here.
