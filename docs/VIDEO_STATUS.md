# Base-X1 video verification

Active path: `rtl/sharpx1.v` instantiates `rtl/legacy/x1_vid.v` and the
enabled/divided-clock `crtc6845s`. The simulator uses that same machine, not
the reference-only legacy wrapper. Complete Turbo 400-line video is not implemented.
An experimental [graphics raster mapper](TURBO_RASTER_STATUS.md) now handles
low, repeated and alternating-page addressing independently of text MA;
clocks/fonts/native high-scan acceptance remain open.
Experimental Turbo page/blackclip tests now run through the same renderer;
see `TURBO_STATUS.md`. They do not extend this base 200-line milestone to
400-line, high-speed PCG or authentic Kanji support.

## Pixel qualification correction

RGB was registered one master edge after the shifter decision, while HBlank
qualified the preceding `disp_d` value directly. Independent CPU-programmed
rasters exposed one blank pixel at the left and a missing last pixel. HBlank
now follows `out_disp`, registered alongside RGB and cleared during reset.
This is a renderer change, not a screenshot crop or simulator-only workaround.
Vertical timing and sync outputs are unchanged.

The new `verilator/tests/test_video_modes.py` builds original Z80 programs,
loads them through the existing RAM diagnostic bootstrap, and writes text,
attributes, all GRAM planes, palettes and CRTC through actual CPU I/O. It
checks every captured RGB pixel against separate formulas/font data, not
against a hash generated by the renderer. The PPI mode write activates DAM;
the fixture clears DAM before the subsequent display-width write.

## Confirmed simulation results, 2026-10-04

All six basic cases below pass with intra-assignment delays in both baseline
32 MHz system / 28.571428 MHz video and optional single 28.636364 MHz master
configurations. Graphics/mixed cases run for one second (32000000 reference
cycles); text cases now run for 200 ms (6400000 reference cycles), masking
GRAM with real palette writes instead of clearing unused graphics memory.
Each uses deterministic RAM-bootstrap reset (reset length includes diagnostic
loading and is printed per case), then verifies a completed 200-line
active raster after the CPU reaches HALT with its `VID!` marker. No IPL/game
boot is implied by this diagnostic.

|---|---|---|
| Three graphics planes, eight colors/rows | `d38612f0d59db725` | `e0aa09561ecc6b25` |
| Character ROM, white text | `43f94f4bddd972b5` | `38336804c6381245` |
| Reversed text, custom palette, raw-color priority | `41fb70199598fb75` | `e77049b8436d71c5` |

The baseline full existing diagnostic suite also passed after this renderer
change. The combined single-clock run timed out on its final video case on a
host concurrently running many sibling-core simulations; rerunning that same
case with a 600-second wall-clock allowance passed with the expected pixels.
That does not claim the rest of that interrupted single suite ran.

Additional pattern cases vary every character and text color/reverse attribute,
use CRTC start address `0x7d5`, and wrap the 2 KiB text/attribute aperture.
Both fast and delay-aware baseline pattern cases pass: 40 columns `1409e31fbcaabea4` and
80 columns `d276b3ec474bc3f4`. Live 40-to-80/80-to-40 mixed-mode transitions
also pass, returning the same independently calculated hashes as cold-start
mixed rasters. The opposite width runs for about 60 ms before the CPU changes
the PPI width bit and CRTC registers; no machine reset is used for the switch.
An initial pattern oracle inverted the font bit before color masking; the
correct X1 behavior reverses the three-bit color after masking, cross-checked
against local MAME `x1_v.cpp`. The expected-pixel formula was corrected;
no renderer change was made to accommodate that incorrect oracle.

Double-width/double-height text and three-plane PCG raster fixtures also pass
in fast and delay-aware baseline models at both widths. The stretch fixture
uses attribute `0xc7` and independently doubles font coordinates. The PCG
fixture uses attribute `0x27`, repeatedly writes `0xaa/0xcc/0xf0` through
actual beam-addressed CPU ports, then checks all pixels after HALT. It does
not establish exact native scanline trapping. Pattern/stretch run for 200 ms;
PCG runs for 300 ms. All twelve static cases passed together in the
delay-aware baseline and single-clock models on October 4. Both mixed-width
transitions also passed in both configurations.

Blink-phase fixtures now use attribute `0x17` and the actual MR16 firmware's
500 ms output toggle, without forcing a simulation input. Fast baseline
captures at 200 ms match ordinary text; 700 ms captures reverse every
three-bit text color. Both widths pass: reversed hashes are
`aa3e96f84b15d4f5` (40) and `a8c19af3abc716c5` (80). Delay-aware baseline
and single-clock phase checks also pass at both widths. Together, sixteen
static cases and two live width transitions now pass in each configuration.
Post-change warm-reset, baseline clock/FST, keyboard-poll, memory and graphics
bus checks pass as well. This verifies the implemented
firmware cadence, not the real keyboard controller's timing against hardware.

The runner also reports the last settled rising-edge HS/VS periods, sampled
on `clk_sys`. Independent fixture totals are 1792 video-master edges per line
at either width and `(32*8+2)=258` lines per frame (462336 master edges).
Period assertions allow only one system-clock sampling interval plus 1 ps,
not a broad percentage tolerance. Text at both widths passes in baseline,
single-clock and fast models: baseline line ~62.72 µs/frame ~16.18176 ms;
single line ~62.57778 µs/frame ~16.14507 ms. These are the fixture's programmed
CRTC totals, not a claim of authentic hardware refresh. The final expanded
matrix passes all sixteen cases and both mixed-width switches in each
delay-aware configuration with these period assertions enabled.

## Reproduction

From `verilator/`:

```sh
make headless single fast
python3 tests/test_video_modes.py ./obj_dir_headless/Vtop --timeout 600
python3 tests/test_video_modes.py ./obj_dir_single/Vtop --timeout 600
python3 tests/test_video_modes.py ./obj_dir_fast/Vtop --kind mixed --transition --timeout 600
```

`make test`, `test-single` and `test-fast` include the static raster and mixed
transition checks. On a busy host use `VIDEO_TEST_FLAGS='--timeout 600'`.
`--output obj_dir_fast/video-modes` retains actual PPMs and diagnostic binaries.

## Remaining acceptance

- PCG raster/readback does not prove exact native scanline timing.
  Independently verify the character ROM and blink cadence against hardware.
- Check measured line/frame timing and mode-change transients against hardware.
- The five-game bounded control gate is reached: Druaga, Xevious, Mappy and
  Galaga have live player-movement checks; Shanghai has native cursor/selection
  and matching-pair removal. Other titles/boards remain bring-up evidence,
  not verified gameplay. Broader actions, music and level compatibility remain
  separate gates; see `COMMERCIAL_COMPATIBILITY.md`.
- The current pixel-qualification change has a successful source-bound
  single-clock Quartus fit with positive analyzed timing; see `QUARTUS_BUILD.md`.
  Full constraints/CDC and actual MiSTer acceptance remain open. Previous
  hardware observations do not validate this new RBF.
